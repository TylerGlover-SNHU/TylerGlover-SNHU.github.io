## Enhancement Two: Software Design and Engineering
The artifact selected for the software design and engineering enhancement was the same as the other two enhancements. During CS-370, which focused on machine learning concepts, we trained a neural network to recognize handwritten digits in the MNIST dataset. Because my main area of interest in computer science is machine learning, this presented me with an opportunity to create an application that used a trained machine learning model. In CS-370, we were not concerned with making a usable application, and no new data beyond the MNIST dataset was ever classified. In fact, throughout the class, we largely stayed within the confines of the dataset with which we were working. I wanted to explore how well a model trained on the MNIST dataset generalizes to photographs of handwritten digits. The command line interface created allowed users to classify their own images, which is an application of the concepts explored in the original artifact. 

I met the last two course outcomes with this enhancement. The first of the two states, "Demonstrate an ability to use well-founded and innovative techniques, skills, and tools in computing practices for the purpose of implementing computer solutions that deliver value and accomplish industry-specific goals." An exploration of the topic was taken and implemented so that a user can perform the classifications without knowledge of machine learning. Machine learning is a field that continues to innovate and is becoming one of the most talked about tools in the computer science space. The second outcome completed states, "Develop a security mindset that anticipates adversarial exploits in software architecture and designs to expose potential vulnerabilities, mitigate design flaws, and ensure privacy and enhanced security of data and resources." The application makes use of a few dependencies: keras, PIL, NumPy, and rich. Up to date versions of these libraries were used, and no recent vulnerabilities have been identified in these dependencies. Additionally, the input function in Python which returns a string is generally safe, and a default clause was used in the match statement which processes the user's menu selection so that all input values are handled. Potential errors, such as no image matching the file name, are handled in try/except blocks. Finally, the directory for the handwritten digit images is restricted to a specific directory. This prevents malicious users from accessing system files with the tradeoff that users must make use of this directory. 

The main challenge I faced while completing this enhancement was formatting new image data. Images were easy enough to load, but the loaded image object was not in the same format as the data which trained the neural network. The first few steps were clear from an understanding of the MNIST dataset obtained through previous experiments and previous reading. Since the MNIST dataset consists of images which are 28 by 28 pixels in grayscale encoding, the images were downscaled and converted to grayscale. Next, they were converted to a NumPy array. The array is formatted like the training data by converting it to a single column vector. This is where I started to have some trouble. Normalizing and feeding this vector into the model did not give good results. I compared the training data to the new vectors. There is a lot of background noise because the new images used by the application were generated from friends and family writing the digits 0 through 9. An image taken with their cellphones has a lot more noise than the MNIST samples. To decrease this noise, I subtracted the minimum grayscale value from the whole array which brings the background noise close to zero. The array data was then normalized using the maximum value. Finally, I set the values that were close to zero by iterating through the array. This created a new datapoint that was more similar to the training data. I also used the Python PIL library for the first time to handle image processing tasks. The PIL documentation made this a relatively simple task.

## Enhancement Three: Databases
The artifact selected for the database enhancement was the same as the other two enhancements. During CS-370, which was focused on machine learning concepts, we trained a neural network to recognize handwritten digits in the MNIST dataset. When I originally trained the artifact, we were only concerned with model performance with respect to the MNIST dataset test data; however, I wanted to explore how well a model trained on the MNIST dataset generalized to photographs of handwritten digits. A command line interface application was created using a model that was found to perform well within the confines of the MNIST dataset. For this enhancement, a database was added to the application which allows the application to keep a record of digits that are classified. This allows us to further explore model performance as it applies to new data from outside the MNIST dataset. 

This enhancement reinforced the completion of the course outcome which states, "Employ strategies for building collaborative environments that enable diverse audiences to support organizational decision-making in the field of computer science." The addition of the database for the command line interface application allows others to view the data that has been created so that model performance can be reviewed. Because this project is a further exploration of machine learning algorithm performance, exposing the model performance statistics allows others to improve the existing algorithm to better account for external data. Also, the new image data is saved as part of the database which can refine new models. 

I found this enhancement to be challenging. I chose to work with SQLite instead of MySQL. This is because SQLite creates a local database file that does not need drivers and a larger environment to function. This may not be appropriate for production level software, but it is acceptable for a local command line interface. SQLite has the advantage of creating a file that is easily accessible and sharable. Since the goal of this application is to explore model performance through classification data stored in a database, this seemed like a positive tradeoff. The biggest roadblock that I encountered was storing the data in the correct format in the SQLite database. Some values were accidentally stored in their binary form instead of a float or integer. This made it more difficult to work with when the data was retrieved. After a good deal of troubleshooting, I was finally able to resolve the issue by casting the data points to the correct data type before performing the insert query. After this correction, the retrieved data was much easier to work with. Additionally, this is the first time that I have saved larger files in a database. Previously, I had saved simple data types like integers, floats, and strings. For this project, I wanted to save image data in the database. This was accomplished by converting the PIL image object into bytes before storing it as a BLOT (binary large object). I learned how to do this through the PIL and SQLite documentation.

Once the application was finished, I used it to classify the new image data I had acquired. I did not expect very high accuracies when classifying this data because the MNIST dataset is standardized, and all data is collected in the same manner; however, I wanted to classify real world data and explore how well the MNIST dataset would generalize to this application. Using the application I created to summarize the data, we see an overall accuracy of 71%. This value may be lower than hoped for, but it does give us insight into this more general application. The current application can be easily adapted to examine other trained neural networks and other algorithms. Using the application, we can dive deeper into the classification statistics. Some digits were classified very accurately. Digits 1, 2, and 3 were able to be classified with 100% accuracy. Digits 0, 4, 6, 7, and 8 were classified with similar accuracy to the average. The model did not perform well with digits 5 and 9 with 5 being classified correctly 25% of the time and 9 never being classified correctly a single time. In general, the average confidence level for each digit classification lined up with the accuracy for the digit. This is what we would expect since we would hope that our model would be less confident in its answer if it were wrong. The main exception to this is the 9 digit which had an average confidence level of 83% which is higher than the other digits with low accuracy. This project can be used as a strong starting point for model refinement before being applied more broadly.
